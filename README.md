# OpenWalk

OpenWalk is a mobile-first, offline-capable web map that helps people find their way
around a place on foot using their phone's GPS. Open it in a browser, allow location,
search for a building or a service, and get a walking route drawn on the map.

OpenWalk is generic by design. The application knows nothing about any particular
place. A campus, a park, museum grounds, or a fairground is a **site**: a directory of
configuration and data that the same code renders. Adding a site means adding a
directory and running the data pipeline; the application code does not change.

## How it works

- **Static site.** nginx serves a bundle of HTML, JavaScript, map tiles, and site data.
  There is no application server in version 1.
- **Everything runs in the browser.** Map rendering (MapLibre GL JS with self-hosted
  vector tiles), routing, search, and all personalization happen on the device.
- **Privacy by construction.** A user's position never leaves the phone. No request
  carries coordinates, so there is nothing to log or breach. No analytics, no
  third-party scripts.
- **Offline after first load.** Installed to the home screen, the app keeps working
  without a network connection.

## The site model

Each site is a directory, `sites/<site-id>/`, with this content:

| File                                               | Purpose                                                            |
| -------------------------------------------------- | ------------------------------------------------------------------ |
| `site.yaml`                                        | Name, boundary, default view, tile layers, categories, attribution |
| `places.yaml`                                      | Curated places: numbers, names, keywords, category, entrance       |
| `overlay/`                                         | An optional official map image and its georeference                |
| `raw/`                                             | Downloaded source data (treated as data only)                      |
| `places.geojson`, `walkways.geojson`, `graph.json` | Generated by the pipeline                                          |

This repository ships one example site. A real site is its own repository, cloned into
`sites/` for local work and ignored by git here, so an institution's names, coordinates,
and map images never enter this repository's history. To deploy a site, its repository
builds an image from the generic web image and copies the site directory in.

## Adding a site

A site is built with the Python pipeline in `tools/pipeline/`; its README covers the
one-time setup. The example site under `sites/tuscawilla-park/` shows every file
described here. Paths below are relative to the repository root.

1. **Create the site directory.** A real site is its own repository cloned to
   `sites/<site-id>/`; the id is lowercase words joined by hyphens.
2. **Write `site.yaml`.** The id, a display name, the boundary as an OpenStreetMap way
   or relation id or a south-west-north-east bounding box, and the default view.
   `packages/schema/schemas/site.schema.json` lists every setting.
3. **Fetch OpenStreetMap data.** `openwalk-pipeline fetch sites/<site-id>` queries the
   Overpass API for everything inside the boundary and caches the result in `raw/`.
   The cache is reused until `--refresh` is given. Commit it if the licence allows, as
   the example does: OpenStreetMap data is ODbL.
4. **Build.** `openwalk-pipeline build sites/<site-id>` writes `walkways.geojson` and
   `graph.json`, then `places.geojson` and `overlays.json` once their inputs exist. It
   reports ways excluded as unpaved, places whose entrance is far from any walkway,
   and whether the network is in one piece.
5. **Write `places.yaml`.** Every destination: an id, a name, a category, search
   keywords, and a position given as an OpenStreetMap element, a hand-placed location,
   or a hand-placed entrance. Mark each `verified: true` only after checking it on
   foot. Rebuild.
6. **Check it on a map.** `openwalk-pipeline debug sites/<site-id>` writes
   `debug.html`, a page that draws everything over satellite imagery. Clicking the map
   prints coordinates in the order the YAML files use; the view is kept in the URL
   hash so a spot can be linked to, and `?hide=overlay,places` opens with layers off.
7. **Close gaps in the network.** Where OpenStreetMap lacks a paved connection, draw
   it in `walkways.yaml` with coordinates taken from the page. Each end within a few
   metres of a mapped walkway is joined to it. Mapping the connection in
   OpenStreetMap afterwards is the lasting fix.
8. **Add an official map, optionally.** Put a PNG of it under `overlay/` and list
   control points in `site.yaml`: a pixel in the image paired with the OpenStreetMap
   element or position it depicts. The build fits the image to the ground and reports
   the residual error in metres. Permission from the map's owner is needed to display it.

Which ways count as walkways is set per site under `walkways` in `site.yaml`:
the highway values admitted, surface values treated as unpaved, whether parking aisles
and which minor roads may be walked as a last resort, and the snapping distance for
hand-drawn ways.

## Repository layout

```
apps/web/          the browser app (Vite + TypeScript, no framework)
packages/routing/  pedestrian routing: graph, snapping, shortest paths (pure, tested)
packages/search/   fuzzy search over a site's places (pure, tested)
packages/schema/   shared schemas for pipeline output and the app
sites/             the example site; real sites are separate repositories
tools/pipeline/    Python data preparation
deploy/            Dockerfiles, compose and stack files, nginx config
docs/              requirements, architecture, device testing
```

## Developing

Requires Node 24 (`.nvmrc`) and Docker with the compose plugin.

```
npm ci              # install exact versions from the lockfile
npm run dev         # Vite dev server for apps/web
npm test            # Vitest across every workspace
npm run check       # lint, format check, typecheck, test: what CI runs
npm run build       # production bundle in apps/web/dist
docker compose -f deploy/compose.yaml up --build   # nginx serving the bundle
```

Testing on a real phone, including HTTPS on a local network, is described in
`docs/DEVICE_TESTING.md`. See `CONTRIBUTING.md` before opening a pull request.
